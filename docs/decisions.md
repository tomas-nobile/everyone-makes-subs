- 2026-09-25 · LIVE-API: F17.2 hybrid VAD is a NO. Sending `audioStreamEnd` at every ≥ 500 ms pause (`VAD_END_MS=500`, same file, same key, minutes after the baseline) stalled the session: first caption after 27 s and 12 phrases in 122 s, against 3 s and 39 phrases in 96 s without it — after each `audioStreamEnd` the session behaves like a fresh one (the 15–20 s warm-up of F06.1), so every pause costs more than it saves. The docs' hybrid-VAD recipe is written for turn-based voice agents, not for a stream that never ends. Run killed at 122 s (no JSON: the checkpoint is per finished run). `VAD_END_MS` stays in the code, default 0. Next try: the server-side `automaticActivityDetection.silenceDurationMs` (`ASR_SILENCE_MS`).

- 2026-09-24 · LIVE-API: after `audioStreamEnd` the old session sends its final (full, corrected utterance) within ~1 s, while a FRESH session can take 15–20 s to emit its first interim. So a rotation holds the new session's output until the old final (≤ 3 s, else the old session's last interim), publishes it, then ignores the old session. Verified on `samples/es.mp3` with `SESSION_ROTATE_SEC=30`: 3 rotations, same text as without rotation, 0 duplicates, 0 gaps (F06.1). `DEBUG_ASR=1` logs every session's messages.
- 2026-09-24 · DECISION: with real audio the Live API keeps one utterance open for as long as the speaker doesn't pause (90 s in the samples) and keeps revising earlier words, so the segmenter now locates the committed words in each interim by alignment (last 3 committed words near the expected position, else edit distance) and runs LocalAgreement only on the uncommitted tail; a long final is split into ≤ 18-word phrases. Before: 5-word fragments every ~6 s and a 233-word dump at the end; after: 34–40 phrases per 90 s (F04.1/F03.2).
