# Everyone Makes Subs — Technical blueprint

> Nerdearla Vibeathon 2026. Deadline: Sept 25, 12:00 ART. Model names and Live API field names come from the September 2026 docs: **phase 1 exists to verify them** before writing the rest.

## What changed from v1

| # | Change | Why |
|---|---|---|
| 1 | The operator is not a developer: **desktop app with an installer** (Electron) + first-run setup wizard in the browser. Docker remains for servers and for the judges | "Download, double-click, paste the key" |
| 2 | **Room station** (`/station/:id`) as the main source: one laptop per room connected to the mixing console, audio through the browser | It is the simplest option for a production person; RTMP and SRT move to "Advanced" |
| 3 | **Public access modes** (`lan` for the demo; Tailscale Funnel or a Cloudflare named tunnel for a real event). The Cloudflare quick tunnel is ruled out because it does not support SSE | Phones and the other laptops must reach the server; `getUserMedia` requires HTTPS outside `localhost` |
| 4 | **A single SSE stream per stage with all languages** | Switch language without reconnecting, bilingual mode for free, less server code |
| 5 | **Audio clock = bytes read from the source**, not bytes sent to Gemini | With a VAD that does not send silence, the clock stalled and the SRT drifted |
| 6 | RTMP and SRT through **MediaMTX**, not `ffmpeg -listen` | `-listen` supports one stage per port |
| 7 | **Dedupe by aligning normalized words** | The ASR final changes punctuation and capitalization relative to the interim |
| 8 | **"What did I miss?" summary generated by the server** every 60 s and cached | If it is per click, cost grows with the audience |
| 9 | **Loading a talk forces a rotation** at the next silence | Otherwise the glossary took up to 9 min to reach the ASR |
| 10 | **Agenda pasted as text** → Gemini turns it into talks per room, with pregenerated glossaries | 10 rooms × 8 talks = 80 manual entries |
| 11 | **Persisted config** in `data/config.json` and `data/stages.json` | A restart mid-event wiped everything |
| 12 | The `device` and separate `hls` sources are removed (`url` remains) | `device` does not work in Docker on Mac/Windows; the room station covers that case |
| 13 | Fixed Dockerfile (standalone yt-dlp + deno, multi-stage, `.dockerignore`) | The yt-dlp zipapp needs python3, which `node:22-slim` does not include |
| 14 | Forced commit at a comma from ~8 stable words; 4.5 s timeout | With 6 s, the real p95 would have been 7–8 s |
| 15 | Plan trimmed to ~13 h with an explicit cut order | The 18 h plan does not fit |

## Three ways to run it, one server

```
                ┌───────────────── server/ (Fastify + pipeline) ─────────────────┐
                │   imported as a library: startServer({ dataDir, port })        │
                └───────────┬───────────────────────┬──────────────────┬─────────┘
                            │                       │                  │
      app/ (Electron)       │       Dockerfile      │     npm run dev  │
  main.ts: startServer() +  │   CMD node server/... │   (development)  │
  window → /setup or /admin │                       │                  │
  powerSaveBlocker, tray    │                       │                  │
```

- **Desktop app (non-developer operator):** the Electron main process calls `startServer()` on `127.0.0.1:8080` and opens a `BrowserWindow` at `/setup` (first time) or `/admin`. `dataDir = app.getPath('userData')`. Tray icon with status. If the window is closed: "Stop the captions?".
- **Docker (server or judges):** `docker compose up`, with the key via env or via the wizard.
- **Development:** `npm run dev` with `FAKE_BACKEND=1`.

## First-run setup (no terminal)

`/setup` appears as long as `config.json` has no valid key.

1. **Paste your Gemini API key.** Link to AI Studio and 3 steps with screenshots. A "Test" button that makes a minimal call to Flash-Lite and shows ✓ or the error in plain language ("The key is not valid", "The key belongs to a project without access to this model").
2. **Choose a password for the Dashboard.** Replaces the `ADMIN_TOKEN` printed to the console (which still exists via env in Docker).
3. **How will phones get in?** A guided checklist; the details are in the next section.
4. **Rooms.** "Load the agenda" (paste text) or "Create rooms manually", or "Try with sample data" (2 rooms with the samples).

The key is stored in `data/config.json` with `0600` permissions. If `GEMINI_API_KEY` comes from env, it takes priority and step 1 is skipped.

### Wizard step 3: internet access

The wizard does not move on until the public address responds from outside.

**With Tailscale (recommended):** a 4-item checklist. Each item is enabled once the previous one shows ✓.

| Item | How it is detected or done (`server/src/public/tailscale.ts`) |
|---|---|
| 1. Install | Looks for the binary: `tailscale` on the `PATH`; on Mac `/Applications/Tailscale.app/Contents/MacOS/Tailscale`; on Windows `C:\Program Files\Tailscale\tailscale.exe`. If it is not found, a "Download" button (tailscale.com/download) and "I've installed it" to search again |
| 2. Sign in | `tailscale status --json`: `BackendState === "Running"`. If not, `tailscale up` (opens the login in the browser) and the status is polled every 2 s |
| 3. Enable public access | `tailscale funnel --bg 8080`. If the account does not have Funnel or HTTPS enabled, the CLI prints a permission link: it is parsed, opened with `shell.openExternal`, and the UI shows "Click Enable and come back". Then the command is retried |
| 4. Test from outside | The URL comes from `Self.DNSName` in `status --json` (`https://everyonemakessubs.<tailnet>.ts.net`). The server requests itself at `GET <url>/api/health?nonce=<n>` and checks the nonce |

- `--bg` makes the Funnel persistent: it survives app restarts.
- In Docker, the container cannot see the host's Tailscale: the wizard shows the command to run on the host (`tailscale funnel --bg 8080`) and only does item 4.
- In the Dashboard: a "Reachable" badge next to the address, with a `/api/health` check through the public URL every 60 s. If it fails, an alert appears at the top: "Phones can't get in".
- **Validate tonight:** on Mac, that the installed Tailscale version accepts `funnel` via the CLI (the docs point to the open source variants) and that the Electron session can execute the binary.

**With Cloudflare:** 3 steps with instructions for the Cloudflare dashboard (create the tunnel, choose the hostname pointing to `http://localhost:8080`). Then the operator pastes the token and the address, and the app runs `cloudflared tunnel run --token <token>` (binary downloaded on first use) and runs the same nonce test.

**Other options** (collapsed): "This WiFi only (for testing)" and "I already have a server with a public address" (`PUBLIC_URL`).

## Public access (tunnel)

> **Correction to the first version of this document:** the Cloudflare quick tunnel (`trycloudflare.com`) **does not support SSE** and cuts off at 200 in-flight requests (returns 429). It cannot be used as the caption transport.

| Mode | When | How |
|---|---|---|
| `tailscale` (default for the demo) | Internet access without your own domain and without touching code | `tailscale funnel 8080` → `https://everyonemakessubs.<tailnet>.ts.net`, fixed and with HTTPS. Free on all plans (beta). It has unpublished bandwidth limits: load test it |
| `lan` | Local testing only | QR with `http://<local-ip>:8080` |
| `cloudflare` | Real event | Named tunnel with your own domain on Cloudflare. The operator creates it from the web dashboard and pastes the *token* into the wizard; the app runs `cloudflared tunnel run --token <token>`. No quick-tunnel 200 limit. Load test SSE before the event |
| `url` | Behind your own proxy or server | `PUBLIC_URL=https://...` |

- **All QR codes and links use `publicUrl`.** If it changes, the Dashboard warns: "The address changed: reprint the QR codes".
- In `lan` mode, room stations on *other* laptops cannot use the microphone (HTTPS is required).
- Station audio also goes up through the tunnel: about 32 KB/s per room in PCM (about 320 KB/s with 10 rooms). If the tunnel limits bandwidth, compressing in the browser (Opus via `MediaRecorder` + ffmpeg on the server) is the next improvement.
- **Transport fallback (optional):** if the client detects that SSE delivers no events within 5 s, it switches to polling `GET /api/stages/:id/events?after=<seq>` every 1 s. Each request lasts milliseconds, so it would also work behind buffering proxies.

## Data model

```ts
type SourceSpec =
  | { kind: 'station' }                                    // audio over WS from /station/:id
  | { kind: 'url'; url: string }                           // YouTube (yt-dlp) or any URL ffmpeg can read
  | { kind: 'file'; path: string; loop?: boolean }         // uploaded from the Dashboard
  | { kind: 'mediamtx'; path: string };                    // rtmp://host:1935/<path> or srt streamid=<path>

type StageState =
  | 'idle'          // stopped
  | 'connecting'
  | 'live'          // there is speech and captions
  | 'paused'        // there is signal but silence > 20 s (pause, applause, short break)
  | 'no_signal'     // the source sends no audio (station closed, stream down)
  | 'degraded'      // running with delay or errors
  | 'error';        // retrying

interface Stage { id: string; name: string; source: SourceSpec; targetLangs: string[];
  state: StageState; talkId?: string; viewers: number; }

interface Talk { id: string; stageId: string; title: string; speaker?: string;
  abstract?: string; lang?: string;          // declared or detected language
  startsAt?: string; endsAt?: string;        // from the agenda
  glossary: Glossary; status: 'next' | 'live' | 'done'; }

interface Glossary {
  asrVocabulary: string[];                   // ≤100 → customVocabulary
  doNotTranslate: string[];
  preferred: Record<string, Record<string, string>>;  // term → { es: '...', pt: '...' }
  replacements: Record<string, string>;     // "cubernetes" → "Kubernetes"
}

interface Segment { seq: number; talkId: string; src: string; text: string;
  tr: Record<string, string | null>;        // null = translation failed
  t0: number; t1: number;                    // seconds of audio since the start of the talk
  kind: 'speech' | 'sound' | 'audience';     // [applause], (audience question)
  ms: { asr: number; mt?: number }; }
```

## Per-stage pipeline

### 1. AudioSource

Single contract: PCM s16le, mono, 16 kHz, 3,200-byte chunks (100 ms).

```bash
# file (simulates real time)
ffmpeg -re -i samples/en.mp3 -f s16le -ac 1 -ar 16000 pipe:1
# YouTube: yt-dlp resolves the direct URL and ffmpeg reads it (-re only for VOD)
yt-dlp -f bestaudio -g "$URL"  →  ffmpeg [-re] -i "$DIRECT" -f s16le -ac 1 -ar 16000 pipe:1
# MediaMTX (OBS publishes to rtmp://host:1935/stage1)
ffmpeg -i rtmp://127.0.0.1:1935/stage1 -f s16le -ac 1 -ar 16000 pipe:1
```

**Room station** (`/station/:id`, opened on the room's laptop):

- `getUserMedia({ audio: { deviceId, echoCancellation: false, noiseSuppression: false, autoGainControl: false } })` → `AudioWorklet` that downsamples to 16 kHz, converts to Int16 and sends binary over `WS /api/stages/:id/ingest?key=<stationKey>`.
- `stationKey` is per room and is included in the station link/QR: the operator does not type anything.
- **10 s ring buffer in the browser:** if the WS drops, it reconnects and resends.
- Wake Lock, and a warning if the tab goes to the background.

**Robustness rules:**

- `audioClock = bytesReadFromSource / 32000`. All `t0`/`t1` values come from here. What is sent to Gemini is a separate count.
- If ffmpeg exits: restart with backoff (1, 2, 4… 30 s) and state `no_signal`.
- 30 s ring buffer on the server side. If the session drops, audio accumulates and is resent. If the lag exceeds 10 s, silent chunks are dropped.

### 2. Meter / VAD

- RMS per chunk. Silence = RMS below the threshold for more than 400 ms. The threshold calibrates itself: 10th percentile of the RMS over the last 30 s, ×2.
- Uses: rotation timing, stop sending long silences (> 2 s, with 300 ms of pre-roll), level for the VU meter, and the `paused` and `no_signal` states.

### 3. TranscribeSession

```ts
const session = await ai.live.connect({
  model: cfg.TRANSCRIBE_MODEL,
  config: {
    responseModalities: [Modality.TEXT],
    inputAudioTranscription: {
      languageCodes: talk.lang ? [talk.lang] : [],   // [] = auto + code-switching
      customVocabulary: talk.glossary.asrVocabulary,
      mode: 'VERBATIM',
    },
  },
  callbacks: { onmessage, onerror, onclose },
});
```

**Three questions phase 1 must answer with real audio, before writing the Segmenter:**

1. Are interims **cumulative** (the whole utterance so far) or **deltas**? The Segmenter always receives the accumulated text of the current utterance; if deltas arrive, they are concatenated in `TranscribeSession`.
2. With a speaker who does not pause, how often does a final arrive?
3. Does the session keep accepting audio after `audioStreamEnd`? If not, hybrid VAD is not used.

**Rotation (make-before-break):**

```
on each chunk:
  e = elapsed(current)
  if e >= ROTATE_SEC - 5 and !next:  next = connect(sameConfig)        // pre-connect
  if next ready and (e >= ROTATE_SEC and vad.silentFor >= 400ms  or  rotateRequested and silence):
      swap()                                                            // normal case: no overlap
  else if e >= HARD_CUT_SEC:
      swap({ overlapMs: 2000 })

swap({overlapMs}):
  current.sendRealtimeInput({ audioStreamEnd: true })
  prev = current; current = next; next = null
  if overlapMs: the last 2 s of the ring are resent to current
  finals from prev keep reaching the Segmenter until it closes (3 s timeout)
  the first final from current goes through align.trimOverlap(lastCommitted, text)
```

- `rotateRequested` is set by loading a talk or editing the glossary.
- `GoAway` or an unexpected close → immediate `connect` + ring resend.

### 4. Segmenter

```
onInterim(accumulatedText):
  hist.push(norm(text)); stable = commonWordPrefix(hist.last(2))    // LocalAgreement-2
  pend = stable − committed
  if pend ends in [.?!;] and words(pend) >= 5                  → commit(pend)
  elif words(pend) >= 8 and pend contains a comma/conjunction  → commit(up to the last one)
  elif msSinceLastCommit > FORCE_COMMIT_MS and words(pend) >= 4 → commit(pend)

onFinal(text):
  rest = align.stripCommitted(committedInThisUtterance, text)   // word-level alignment
  if rest not empty and !isNoise(rest) → commit(rest)
  reset the utterance
```

- `norm` = lowercase, without punctuation or accents. It is only used for comparison; the original text is published.
- `stripCommitted`: find the smallest index `j` in the final such that `final[0..j]` aligns with the committed text with a word-level edit distance ≤ 20%.
- `glossary.replacements` are applied before publishing.
- **Noise:** empty, punctuation only, identical text repeated 3 times in a row, or text that does not match the talk's language with low RMS (music). Markers like `[applause]` are published as `kind: 'sound'`.

### 5. Translator

One call per commit, with JSON output containing all languages.

```ts
generateContent({ model, contents: prompt,
  config: { responseMimeType: 'application/json', responseSchema,
            thinkingConfig: { thinkingBudget: 0 }, temperature: 0.2 } });
```

```
You are the live captioner for the talk "{title}" ({speaker}) at a technical conference.
Translate the SEGMENT into: {langs}. It may be a fragment of a sentence: translate only
what it says, without completing it. Subtitle style: short and faithful, add nothing.
If the segment is already in a target language, return it unchanged in that language.
DO NOT translate: {doNotTranslate}. Required translations: {preferred}.
CONTEXT (do not translate): {last 3 segments}
SEGMENT: {text}
JSON: {"src":"<iso>", "es":"...", "en":"...", "pt":"..."}
```

- The original (`segment`) is published as soon as it is committed, and the translation (`tr`) when it comes back.
- Concurrency of 2 per stage. The client sorts by `seq`.
- Fallback: 429/5xx → backoff (3 attempts) → `TRANSLATE_FALLBACK_MODEL` → `tr` with `null` (the UI shows the original, flagged).
- If `src === lang` of the target, no call is needed for that language: the original is copied.

### 6. Glossary, agenda and summary (AUX_MODEL)

- **Glossary:** `{title, speaker, abstract, slidesText?}` → JSON `Glossary`. Generated when the talk is created. With an agenda, all of them are generated in a batch (concurrency 4).
- **Agenda:** the operator pastes the text from the conference website as is. The model returns `{ rooms: string[], talks: {room, start, end, title, speaker, abstract, lang}[] }`. A table is shown for confirmation before saving.
- **Talk switch:** at the `startsAt` time, the Dashboard shows "Move to the next talk?" with a button. If nobody responds, it switches automatically at +5 min past the scheduled time, at the next silence longer than 3 s. There is always a "Next talk" button.
- **Summary:** every 60 s, if there were new segments, 3–5 bullet points on the last 5 min per language. It is cached and served to everyone (`GET /api/stages/:id/summary?lang=`).
- **Glossary metric:** count of occurrences of each `asrVocabulary` term in the segments. In the Dashboard: "Kubernetes ✓ 12".

| `GET /api/stages/:id/summary?lang=` | — | Cached summary |

| `GET /api/health` | — | |

Admin auth: password → signed `httpOnly` cookie. `/api/setup` only responds without auth from `127.0.0.1` or while no password exists.

**SSE events** (one stream per stage; each one weighs a few hundred bytes):

```ts
{ type: 'hello',   state, talk, next?, lastSeq }                 // on connect
{ type: 'live',    text }                                       // interim of the original, with masking
{ type: 'segment', seq, src, text, t0, t1, kind }               // confirmed original
{ type: 'tr',      seq, tr: { es, en, pt }, ms }                 // translations of the segment
{ type: 'state',   state, talk?, next? }                        // live/paused/no_signal/...
{ type: 'level',   v }                                          // 0..1, 4 per second, for "speaking…"
```

- `: ping` heartbeat every 15 s. Headers: `Cache-Control: no-cache`, `X-Accel-Buffering: no`.
- **`live` masking:** the last 2 words are hidden unless they match the previous interim.

## Frontend

The visual details are in the prototype (`ui-prototype.html`). Summary:

| Route | Who it is for | Key points |
|---|---|---|
| `/` | Attendee without a QR | "Live now": cards per room with the current talk and one button per language |
| `/s/:id` | Attendee (phone) | Auto-detected language; reading view with the latest sentences in large type; "speaking…"; optional bilingual mode; back to live with a counter; states; summary; download when it ends |
| `/s/:id/tv?lang=&qr=1` | Room screen (TV mode) | 2 huge lines, QR in the corner, break card with the next talk |
| `/s/:id/overlay?lang=&lines=2&size=48&pos=bottom&box=1` | OBS | Transparent; configurator with a preview in the Dashboard that generates the URL |
| `/station/:id?key=` | Room laptop | Choose input, large VU meter, "Test", sending status |
| `/admin` | Operator | Cards per room: status in plain language, VU meter, **last transcribed line**, delay, current and next talk. Details in a side panel |
| `/setup` | First-run setup | Key → password → access → rooms |

**UX rules:**

- TV and overlay work with a **character budget** (about 42 per visible line) and show the tail of the text cut at a word boundary, so a long sentence does not take up 5 lines.
- All operator UI text is in non-technical language. Technical numbers (p50/p95, rotations, 429, US$/h) go inside "Technical details".
- `aria-live="polite"` only on the segments in the chosen language, never on `live`.
- `prefers-reduced-motion`: no entrance animations.
- Typography: Atkinson Hyperlegible (or the system font), 26 px base on phones, `line-height` 1.35, `#F2F2F2` text on `#000`.

## Metrics (in "Technical details")

| Metric | Calculation | Alert |
|---|---|---|
| Delay (what is shown in plain language) | p50/p95 of `segment.published − t1` and `tr.published − t1` over the last 50 sentences | p95 > 6 s → `degraded` |
| `lag` | wall clock − start − audioClock | > 10 s |
| No audio | RMS ≈ 0 | > 30 s → `no_signal` |
| Errors | 429s and session errors | > 3/min |
| Rotations | count and gap duration | gap > 1 s |
| Cost | minutes of audio sent × rate + tokens | — |
| Viewers | open SSE connections | — |

## Scaling (for the README)

1. **Up to ~10–15 rooms:** one laptop with the app or a 2 vCPU container. It is I/O-bound work.
2. **More rooms or more reliability:** a server with Docker (not a laptop), `ROLE=worker|web` with the same image and Redis pub/sub instead of the EventBus (same `publish`/`subscribe` interface).
3. **Larger audience:** `web` replicas behind a proxy or CDN. The AI cost does not change.
4. **Quotas:** Tier 1+ with billing. Peak of 2 Live sessions per room during rotation. Check the project's Live concurrency in AI Studio.
5. **Local/offline:** `SpeechBackend`/`TranslateBackend` with a Gemma implementation (experimental).
